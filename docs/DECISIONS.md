# Decisions log

Running log of choices made while building, per `docs/SPEC.md` Section 0 rule 8: when a requirement is ambiguous, pick the safest option, log it here, and continue.

| Date | Area | Decision | Why |
|---|---|---|---|
| 2026-11-08 | Tooling | Package manager is `pnpm` | Spec Section 2 decision; faster installs, strict node_modules |
| 2026-11-08 | Tooling | Tailwind CSS v4 via `@tailwindcss/vite` plugin (CSS-first config, no `tailwind.config.js`) | Current stable Tailwind major; spec only pins "Tailwind CSS", not a version |
| 2026-11-08 | Tooling | ESLint (flat config) + Prettier for formatting, oxlint removed | Spec CI requires "lint, typecheck" via standard ESLint; oxlint was Vite's scaffold default but not part of the fixed stack |
| 2026-11-08 | PWA | `public/icon-192.png` / `icon-512.png` are solid-color placeholders (brand blue), not a real app icon | Unblocks the PWA manifest in M0; swap for real artwork once branding (Section 17 open item 5) is settled |
| 2026-11-08 | Tooling | Pinned `typescript` to `^5.9.3` instead of the newly-released TS 7 | `typescript-eslint` 8.x does not yet support the TS 7 API; revisit once typescript-eslint adds support |
| 2026-11-08 | Backend | Switched the entire backend from Supabase (Postgres+RLS+Edge Functions) to Convex, at the user's explicit request after a tradeoffs discussion | Convex has no RLS — authorization now lives entirely in `convex/lib/authz.ts` helpers that every query/mutation must call by hand (see `convex/schema.ts` header comment). Sections 2–6 and 12 of `docs/SPEC.md` were rewritten accordingly; pgTAP policy tests are replaced by `convex-test` unit tests (not yet written — M1 follow-up) |
| 2026-11-08 | Backend | QR tokens no longer need HMAC signing | Since only our own `issueQr`/`scanQr` mutations can ever create or consume a `qrTokens` row, Convex's server-trust boundary already gives the "server decides what is true" guarantee the SQL version got from a signed, client-opaque token |
| 2026-11-08 | Design | Added JetBrains Mono as a monospace accent font (tags/codes/countdowns only, Inter stays the body font); redesigned the Auth page away from the generic centered-badge/segmented-tab/blue-slab-button template | User feedback: the first Auth page draft "looks AI slop." Rebuilt with a dark hero, underline inputs, and mono-tag accents instead of boxed-everything |
| 2026-11-09 | Testing | Added `convex/vitest.config.ts` (edge-runtime) + `pnpm test:convex` for `convex-test` backend tests, separate from the main jsdom suite | `convex-test` requires the edge-runtime environment per its own docs; needed explicit `include`/`exclude` on both configs after the first run cross-contaminated (the convex config picked up frontend tests and vice versa) |
| 2026-11-10 | Security | Left the `minimatch`/`deepmerge`/`glob` Dependabot alerts (GitHub flagged 2-3 on push) unfixed, after confirming an override breaks the build | Both are transitive **devDependencies** of `vite-plugin-pwa` → `workbox-build`, never shipped to the browser — no runtime exposure. Tried overriding `minimatch` to the patched `11.0.1`; it silently broke `workbox-build`'s internal glob matching (precache dropped from 9 entries to 4, zero KB) because v11's API isn't compatible with what `globby`/`workbox-build` call. A working PWA build outweighs a dev-only DoS advisory with no exploit path here. `deepmerge`'s advisory has no patched version at all. Revisit if `vite-plugin-pwa` ships a workbox-build upgrade. |
| 2026-11-10 | Backend | Added `admin:makeAdmin`, an `internalMutation` — only reachable via `npx convex run admin:makeAdmin '{"displayName":"..."}'`, never from the client | There is deliberately no self-promotion path (SPEC.md §4.3); someone has to become the first admin somehow, and a CLI-only internal function is the smallest possible hole |
| 2026-11-10 | Backend | `deleteMyAccount` repoints the caller's ratings to a lazily-created "tombstone" user instead of leaving `raterId`/`ratedId` optional | Keeps the schema's foreign keys non-optional everywhere else; matches SPEC.md §10's "anonymized, not deleted" requirement for other users' scores |
| 2026-11-10 | Security | Added `vercel.json` with CSP/X-Frame-Options/Permissions-Policy headers, scoped to Convex's domains + Google Fonts | SPEC.md §9 asks for a CSP; adapted from the Supabase-origin version to Convex's `*.convex.cloud`/`*.convex.site` |
| 2026-11-10 | Testing | `getPilotMetrics` (admin-only Convex query) replaces the planned `scripts/export-metrics.sql` | No SQL to export from; computing the §15 targets on demand from the live tables is simpler and always current |
| 2026-11-09 | Performance | Lazy-loaded `ScanPage` (`React.lazy` + `Suspense`) since `html5-qrcode` alone is ~370KB gzipped and only that one route needs it | Keeps the main bundle under the 500KB warning threshold for every route except Scan; home/auth/dashboard first-load stays light per SPEC.md §11 |
| 2026-11-08 | Backend | **Blocker, needs the user**: `convex/_generated/*` cannot be produced from this sandbox — `npx convex dev` requires an interactive browser login, and `npx convex codegen` still needs a real `CONVEX_DEPLOYMENT` to resolve against (confirmed: a placeholder deployment name is rejected by `api.convex.dev`) | Until someone runs `npx convex login && npx convex dev` locally once, `pnpm typecheck`/`pnpm build`/CI will fail on the `../../convex/_generated/api` imports in `src/`. This is expected, not a bug — `convex/_generated` is gitignored like `node_modules`, the same as the Supabase-generated types were before it |
